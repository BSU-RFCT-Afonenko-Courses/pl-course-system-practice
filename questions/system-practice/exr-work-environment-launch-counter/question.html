Сложность: Начальный

Получите отчёт о числе строк утренних измерений готовым инструментом проекта. Маршрут — PowerShell 7/Windows либо fish/Linux. Общие правила подготовки и проверки архива.

Исходное состояние

Комплект содержит самостоятельный вход:

survey/
├── tools/
│   ├── count.ps1
│   └── count.fish
└── result/
    └── current/
        └── morning.txt

В result/current/morning.txt находятся строки A=12 и B=7 в этом порядке. Каждая заканчивается LF; кодировка — UTF-8 без BOM. Каталог назначения result существует, result/line-count.txt и explanation.md отсутствуют. Все файлы и каталоги обычные. Работайте внутри survey; сохраните вход и оба готовых инструмента.

Договор инструмента

Выберите tools/count.ps1 для PowerShell либо tools/count.fish для fish. Исходный текст инструмента предоставлен готовым и сохраняется без изменений. В PowerShell пути передаются параметрами SourcePath и ReportPath; в fish входной путь — первый аргумент, новый отчёт — второй. Относительные пути отсчитываются от рабочего каталога вызова.

Родительский каталог отчёта должен существовать, сам файл отчёта — отсутствовать. При успехе инструмент сохраняет вход и создаёт одну строку lines=N, где N — число строк входа. Тот же текст появляется в терминале; код завершения равен 0. При отсутствующем входе инструмент сообщает причину, возвращает 2 и не создаёт отчёт.

Результат и предъявление

Запустите инструмент для result/current/morning.txt, указав новый отчёт result/line-count.txt. Прочитайте отчёт и установите код завершения. Файл должен содержать lines=2 с завершающим LF в UTF-8 без BOM; в терминале появляется lines=2, код равен 0.

В корне survey создайте explanation.md в UTF-8: укажите ОС, оболочку и её версию, свою команду, рабочий каталог, наблюдавшийся код завершения и соответствие числа строк содержимому входа.

Предъявите ZIP с единственным корнем survey: исходными tools, result/current/morning.txt, полученным result/line-count.txt и explanation.md.

На разборе повторите вызов с новым временным именем отчёта внутри survey. Покажите рабочий каталог, переданные пути, код и результат. Удалите временный отчёт после демонстрации.

Подготовка: вводный разбор запуска и подготовка среды и запуск сценария.

Открытые примеры

Отчёт по двум строкам

В result/current/morning.txt находятся A=12 и B=7 с завершающими LF. Каталог result существует, result/line-count.txt отсутствует. Вызов готового инструмента своего маршрута для этих путей создаёт отчёт с байтами lines=2 и LF в UTF-8 без BOM. Терминал показывает lines=2, код завершения — 0; вход и оба инструмента сохранены. Прочитайте отчёт и установите код вызова.

Повтор с новым именем отчёта

После первого вызова сохранены исходные инструменты, вход и итоговый result/line-count.txt. Для повторного вызова выбрано свободное имя внутри survey, родительский каталог существует. На разборе вызов с этим выходным путём создаёт временный отчёт lines=2 с LF, выводит lines=2 в терминал и завершается с кодом 0. Покажите рабочий каталог, пути, код и чтение отчёта, затем удалите временный файл. Первоначальный отчёт, вход и инструменты сохраняются. Имя временного файла и запись вызова выбираете самостоятельно.

Архив позволяет прочитать отчёт и входы. Вызов, рабочий каталог, переданные пути и код предъявляются при наблюдении запуска. Поведение при отсутствующем входе задано в договоре инструмента; обязательные запуски этой задачи описаны выше.
