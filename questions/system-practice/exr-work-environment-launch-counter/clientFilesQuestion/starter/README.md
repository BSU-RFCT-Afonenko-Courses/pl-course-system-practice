<a id="исходное-состояние-1"></a>

### Исходное состояние

</div>

Комплект содержит самостоятельный вход:

``` text
survey/
├── tools/
│   ├── count.ps1
│   └── count.fish
└── result/
    └── current/
        └── morning.txt
```

В `result/current/morning.txt` находятся строки `A=12` и `B=7` в этом порядке. Каждая заканчивается LF; кодировка — UTF-8 без BOM. Каталог назначения `result` существует, `result/line-count.txt` и `explanation.md` отсутствуют. Все файлы и каталоги обычные. Работайте внутри `survey`; сохраните вход и оба готовых инструмента.

<div>

<a id="договор-инструмента"></a>

### Договор инструмента

</div>

Выберите `tools/count.ps1` для PowerShell либо `tools/count.fish` для fish. Исходный текст инструмента предоставлен готовым и сохраняется без изменений. В PowerShell пути передаются параметрами `SourcePath` и `ReportPath`; в fish входной путь — первый аргумент, новый отчёт — второй. Относительные пути отсчитываются от рабочего каталога вызова.

Родительский каталог отчёта должен существовать, сам файл отчёта — отсутствовать. При успехе инструмент сохраняет вход и создаёт одну строку `lines=N`, где `N` — число строк входа. Тот же текст появляется в терминале; код завершения равен `0`. При отсутствующем входе инструмент сообщает причину, возвращает `2` и не создаёт отчёт.

<div>

<a id="результат-и-предъявление"></a>

### Результат и предъявление

</div>

Запустите инструмент для `result/current/morning.txt`, указав новый отчёт `result/line-count.txt`. Прочитайте отчёт и установите код завершения. Файл должен содержать `lines=2` с завершающим LF в UTF-8 без BOM; в терминале появляется `lines=2`, код равен `0`.

В корне `survey` создайте `explanation.md` в UTF-8: укажите ОС, оболочку и её версию, свою команду, рабочий каталог, наблюдавшийся код завершения и соответствие числа строк содержимому входа.

Предъявите ZIP с единственным корнем `survey`: исходными `tools`, `result/current/morning.txt`, полученным `result/line-count.txt` и `explanation.md`.

На разборе повторите вызов с новым временным именем отчёта внутри `survey`. Покажите рабочий каталог, переданные пути, код и результат. Удалите временный отчёт после демонстрации.

Подготовка: [вводный разбор запуска](https://bsu-rfct-afonenko-courses.github.io/System-Practice/practice/work-environment.html#/sec-work-environment-intro) и [подготовка среды и запуск сценария](https://bsu-rfct-afonenko-courses.github.io/System-Practice/handbook/work-environment.html#sec-reference-script).

# Запуск счётчика строк

</div>

Выберите PowerShell 7 на Windows либо fish на Linux. Комплект содержит готовый самостоятельный каталог `survey` с инструментами и входом `result/current/morning.txt`. Распакуйте его в собственную доступную папку.

Запускайте `tools/count.ps1` в PowerShell либо `tools/count.fish` в fish. PowerShell получает `SourcePath` и `ReportPath`; fish — входной путь первым аргументом и путь нового отчёта вторым. Установите рабочий каталог и согласуйте с ним оба пути. Для Windows используйте подготовку локального сценария из справочника, указанного в условии.

Перед запуском каталог `result` существует, `result/line-count.txt` отсутствует. Передайте утренние измерения инструменту, получите этот отчёт, прочитайте его и установите код завершения. Ожидаются `lines=2` в отчёте и терминале, код `0`. Сохраните исходный вход и оба инструмента.

Запишите среду, команду, рабочий каталог, код и смысл результата в `survey/explanation.md`. На разборе повторите вызов с новым временным именем отчёта и после чтения удалите временный файл. ZIP с корнем `survey` создайте снаружи каталога. Перед сдачей извлеките архив в новую папку, проверьте дерево и прочитайте файлы. Имена учебных файлов и регистр букв сохраняются. Команду запуска выбирайте самостоятельно, пояснение создайте текстовым редактором.
