Сложность: Начальный

Добровольная задача о содержимом коммита, индекса и рабочего дерева. Сохраните исправление названия проекта отдельным коммитом и восстановите прежнюю запись о встрече.

Выберите native Workspace с fish/Linux либо собственную ОС: PowerShell 7/Windows или fish/Linux. Нужны Git с командой restore и текстовый редактор. Краткие сведения об операциях содержит справочник восстановления содержимого; начало работы с комплектом описано в README.

Общие правила подготовки и проверки архива.

Исходное состояние

В каталоге work находится обычный репозиторий с собственным .git. Его ветка main указывает на единственный коммит A. Индекс и рабочее дерево совпадают с A. В нём два текстовых файла:

Файл Единственная строка
README.md Название: учебный проект.
notes.txt Следующая встреча: понедельник.

Файлы имеют кодировку UTF-8 и завершающий перевод строки. В рабочей копии допустимы окончания LF и CRLF.

Подготовка коммита

Измените строку README.md на Название: проект измерений., а строку notes.txt — на Следующая встреча: вторник.. Подготовьте оба файла к коммиту.

Затем примените git restore --staged к notes.txt, сохранив рабочую правку этого файла. После действия в индексе должны находиться новое название проекта и прежняя запись о понедельнике. Рабочий notes.txt продолжает содержать вторник. Зафиксируйте это состояние индекса коммитом B: относительно A он изменяет только README.md.

Восстановление рабочего файла

Примените git restore, чтобы вернуть рабочий notes.txt к записи о понедельнике. Допустимы обычные формы указания пути и источника, сохраняющие требуемые источник и назначение восстановления.

В итоге HEAD выбирает main и коммит B с единственным родителем A. README.md содержит новое название, notes.txt — прежнюю запись о понедельнике; индекс и рабочее дерево чисты. Исходный A сохраняется. Даты и идентификатор нового коммита условием не фиксируются; сообщение выбираете самостоятельно и описываете в нём изменение.

Наблюдение результата

В коротком explanation.md рядом с work укажите ОС, оболочку и версию Git. Сопоставьте содержимое HEAD, индекса и рабочего файла: после снятия подготовки notes.txt и после окончательного восстановления. Объясните, какое состояние попало в B и почему рабочая запись о вторнике сохранялась до второго восстановления.

Для обоих применений restore сохраните короткие результаты существенных status/diff либо покажите действия и состояния на разборе. Полный журнал команд не требуется.

Предъявление решения

В native Workspace работайте в work, а explanation.md сохраните рядом. Сохраните файлы в редакторе и отправьте решение штатной кнопкой PrairieLearn. Сдача возвращает преподавателю историю .git, refs, HEAD, индекс, рабочие файлы и пояснение; вручную создавать ZIP в Workspace не требуется. Повторное открытие среды продолжает выбранную работу.

При работе в собственной ОС подготовьте ZIP или tar.gz с каталогом work целиком, включая .git, и расположенным рядом explanation.md. Имя внешнего каталога и архива выбираете самостоятельно. После извлечения проверьте читаемость истории A → B, содержимое обоих файлов и чистое состояние work.

Оба маршрута сохраняют одинаковые предметные требования. На разборе предъявляются история, пояснение и наблюдения двух восстановлений. Конечные A → B и чистые файлы сами по себе не устанавливают применение двух обязательных restore и промежуточное различие индекса и рабочего файла.

Открытые примеры

Снятие подготовки одного файла

HEAD выбирает A с исходным названием проекта и записью о понедельнике. В индексе и рабочих файлах уже находятся Название: проект измерений. в README.md и Следующая встреча: вторник. в notes.txt. После git restore --staged для notes.txt получается:

Состояние README.md notes.txt
HEAD/A Исходное название Понедельник
Индекс Новое название Понедельник
Рабочие файлы Новое название Вторник

Подготовленная разность касается только README. Сравнение рабочего notes.txt с индексом показывает понедельник → вторник. Короткие состояния и разности после действия либо демонстрация позволяют сопоставить команду с изменением индекса.

Восстановление единственной рабочей правки

Создан B с единственным родителем A: он меняет только README на Название: проект измерений.. HEAD выбирает main и B, индекс совпадает с B. В коммите и индексе notes.txt содержит понедельник, в рабочем файле — вторник. После восстановления рабочего notes.txt посредством git restore во всех трёх состояниях находится понедельник. main и HEAD выбирают прежний B, новое название сохранено, подготовленных и рабочих изменений нет.

Покажите HEAD, оба сравнения и содержимое рабочего файла после действия; объясните различие двух восстановлений. История и чистые файлы подтверждают конечное состояние, а применение обязательных команд и промежуточное различие индекса и рабочего файла устанавливаются по наблюдениям.
