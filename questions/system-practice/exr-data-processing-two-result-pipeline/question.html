Сложность: Средний

Лаборатория хранит результаты подсчёта частиц в пробах. Проверка качества помечает пригодные наблюдения keep, исключённые — skip. Подготовьте одним сценарием сводку пригодных проб по числу частиц и список исключённых проб по коду.

Маршрут — PowerShell 7/Windows либо fish/Linux. PowerShell обрабатывает CSV и передаёт по конвейеру объекты с именованными свойствами; fish обрабатывает текстовые строки. Общие правила подготовки и проверки архива.

Входные данные

Комплект имеет корень processing:

processing/
├── inputs/
│   ├── readings.txt
│   ├── readings.csv
│   ├── no-match.txt
│   └── no-match.csv
└── expected/
    ├── selected.txt
    ├── selected.csv
    ├── excluded.txt
    ├── excluded.csv
    ├── empty.txt
    ├── empty.csv
    ├── no-match-excluded.txt
    └── no-match-excluded.csv

PowerShell использует .csv, fish — .txt; оба формата представляют одни наблюдения. Сохраните все inputs и expected без изменений. Новые учебные файлы создавайте внутри processing.

Основной вход readings содержит записи в таком порядке:

Code — код пробы Units — число частиц State — решение
B03 10 keep
B01 2 keep
B06 9 skip
B02 10 keep
B05 0 keep
B04 20 skip

В no-match находятся B07/1/skip и B08/11/skip в указанном порядке. В .txt запись занимает одну строку Code|Units|State, заголовка нет. В .csv первая строка — Code,Units,State, поля записи разделены запятыми. Входы записаны в UTF-8 без BOM, с LF после каждой строки.

Код состоит из одной заглавной латинской буквы и двух цифр; коды уникальны. Units — целое от 0 до 999 в десятичной записи без ведущих нулей, кроме 0. State — ровно keep или skip. Поля не содержат пробелов, кавычек, разделителей и переводов строки. Допустимо любое число записей, включая ноль: пустой .txt имеет 0 байт, CSV без наблюдений содержит только заголовок с LF. Входные записи заведомо корректны.

Преобразование

Напишите в корне processing один сценарий своего маршрута: Select-Readings.ps1 либо select.fish. Он получает входной путь и два пути результата. Один запуск создаёт обе выборки:

Результат Отбор Порядок Поля
Пригодные State равен keep Числовой Units по возрастанию, затем Code по возрастанию Code, Units
Исключённые State равен skip Code по возрастанию Code, Units

Для Code действует посимвольный порядок A–Z и 0–9. В построении каждого результата соедините через | не менее двух содержательных стадий из отбора, сортировки и проекции. Можно повторно читать вход либо хранить прочитанные данные. Правила должны работать на перестановках и других допустимых записях. Копирование expected, готовый ответ в исходнике и передача готового ответа только на вывод не выполняют требования обработки и содержательного конвейера.

Для readings пригодные записи — B05/0, B01/2, B02/10, B03/10; исключённые — B04/20, B06/9. Для no-match пригодная выборка пуста, исключённая содержит B07/1, B08/11. Открытые образцы находятся в expected.

Формат результатов

В fish непустой результат — строки Code|Units без заголовка и пустых строк, UTF-8 без BOM, с LF после каждой строки. Сравнение с соответствующим expected/*.txt побайтное.

В PowerShell непустой результат — CSV с колонками Code,Units, без #TYPE и дополнительных столбцов, UTF-8 без BOM. Допустимы корректные CSV-кавычки, LF или CRLF, наличие либо отсутствие последнего перевода строки. После разбора совпадают заголовок, значения и порядок записей. Units сохраняет каноническую десятичную запись.

Выборка без записей в обоих маршрутах — файл ровно 0 байт. При входе только из keep пуст второй результат; при нуле записей пусты оба. Повторный успешный вызов заменяет оба прежних результата.

Проверка запуском

Все вызовы выполняйте из корня processing; заранее создайте results. Три пути различны, аргументы передаются правильно, родительские каталоги выходов существуют и доступны для записи. В PowerShell параметры — InputPath, SelectedPath, ExcludedPath; в fish это соответственно первый, второй и третий аргументы.

Выполните три случая одним сценарием выбранного маршрута. Знак * в таблице означает его расширение .csv либо .txt; сценарий получает полное имя файла.

Вход Пригодные Исключённые Файл stderr Код
inputs/readings.* results/selected.*: 4 записи results/excluded.*: 2 записи results/selected.err: пуст 0
inputs/no-match.* results/empty.*: 0 байт results/no-match-excluded.*: 2 записи results/empty.err: пуст 0
inputs/absent.* results/missing-selected.*: отсутствует results/missing-excluded.*: отсутствует results/missing.err: непуст Ненулевой

Перенаправьте stderr каждого вызова в указанный журнал. Перед третьим запуском отсутствуют вход inputs/absent.* и оба missing-результата. После отказа ни один из этих результатов не должен появиться. Диагностика содержит имя отсутствующего входа; её язык, оформление и конкретный ненулевой код выберите самостоятельно.

Stdout сценария пуст во всех случаях. Успешные вызовы оставляют stderr пустым. Ошибки неправильных аргументов, недоступного каталога и повреждённого формата лежат за областью этой задачи.

Пояснение и предъявление

Создайте explanation.md в UTF-8. Укажите среду и версию, три команды и наблюдавшиеся коды. Объясните поля текстовых строк либо свойства и типы объектов между стадиями обоих конвейеров, количество записей для основного входа. Обоснуйте числовой порядок 2 и 10, порядок равных количеств и исключённых проб B04 и B06. Сопоставьте пустую выборку с ошибкой входа, укажите место диагностики и способ сравнения с expected, включая порядок и кодировку.

Предъявите ZIP с единственным корнем processing, исходными inputs и expected, одним сценарием, explanation.md и результатами своего маршрута. В results находятся четыре файла данных: selected.*, excluded.*, empty.*, no-match-excluded.*; три журнала: selected.err, empty.err, missing.err. Файлы missing-selected.* и missing-excluded.* отсутствуют. Служебные файлы редактора не входят в учебный результат.

На разборе выполните сценарий на согласованной перестановке либо другом допустимом наборе и объясните данные на выбранной границе стадий. Применение двух содержательных конвейеров покажите по исходнику.

Подготовка: объектный конвейер, текстовые потоки, вводный разбор, команды обработки и подготовка запуска.

Открытые примеры

Оба вызова выполняются из processing, каталог results существует. Вместо * используется полное расширение выбранного маршрута.

Числовой порядок и два результата

В inputs/readings.* записи идут в порядке B03/10/keep, B01/2/keep, B06/9/skip, B02/10/keep, B05/0/keep, B04/20/skip. Один вызов сценария с выходами results/selected.* и results/excluded.* создаёт:

  • пригодные: B05/0, B01/2, B02/10, B03/10;
  • исключённые: B04/20, B06/9.

При перенаправлении stderr в results/selected.err журнал имеет 0 байт. Код завершения — 0, stdout пуст, входы и expected сохранены. Порядок 2 перед 10 отражает числовое сравнение, B02 перед B03 — дополнительное сравнение кодов при равных количествах.

Пригодных наблюдений нет

В inputs/no-match.* находятся B07/1/skip и B08/11/skip. Тот же сценарий с выходами results/empty.* и results/no-match-excluded.* создаёт первый файл ровно 0 байт, второй — с B07/1 и B08/11 в этом порядке. При перенаправлении stderr в results/empty.err журнал имеет 0 байт. Код — 0, stdout пуст; входы и expected сохранены.

Для обоих примеров действуют объявленные форматы: fish сравнивается побайтно с expected, CSV PowerShell — по колонкам Code,Units, значениям и порядку. Применение содержательных конвейеров и объяснение данных между стадиями предъявляются преподавателю вместе с третьим обязательным случаем — отказом для отсутствующего входа.
